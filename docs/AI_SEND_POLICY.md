# AI 送信ポリシー

Issue #61 の判断記録です。`fix/sensitive-note-review-gate`(PR #85)の実装に基づきます。実装を変える文書ではありません。

## 決定(2026-10-25、所有者方針変更)

- AI 送信境界のブロックは、**認証情報・シークレット検出（credentials）のみ**とする。所有者自身も無料版 Gemini を通常利用しており、通常ノートが Gemini に送られることは許容するという判断。
- 機微語リスト（診断・クローン病・服薬・部屋番号・金融系キーワードなど）によるカテゴリ検出と送信ブロックは**廃止**する。`src/ai-send-guard.mjs` の `inspectAndRedact` は health / financial / location を findings に出さない。これにより #61 / #93 で予定していた語別ラベル付けとルール調整は不要になった。
- 認証情報の検出・マスク・遮断は**従来どおり不変**（credentials は本来ノートに入っていないはずのものへの安全網という位置づけ。認証情報は Bitwarden で管理する運用）。個人情報の伏字（メール・電話・住所など）も従来どおり維持する。
- この変更で置き換えられる過去の決定:
  - 2026-10-23 決定のうち「健康・金融・住所の検出は fail-closed（送らない）」の部分。
  - Issue #94 の「機微カテゴリを含む発言は原文のまま履歴へ保存し、記憶抽出ジョブに積まない」特例。方針変更後は、機微語の有無にかかわらず伏字済み本文を保存し、認証情報を含まない発言は記憶抽出ジョブに積む。
- 既存データへの影響: D1 の `ai_allowed` は自動では変わらない。`review_state = 'pending_confirmation'` / `sensitivity = 'sensitive'` のノートも自動では再評価されず、次回の整理実行・内容更新・一括反映のいずれかで再判定される（整理では全段落が対象になるため、保留は解消し得る）。一括確認では、認証情報を含まないノートは機微語だけを理由に確認待ちにならない。
- 各送信境界のカテゴリ判定の配線（`hasSensitiveCategory` の呼び出し）は互換のため残るが、findings にカテゴリが含まれないため発火しない。ブロック理由は認証情報と構造的に送れない入力のみ。

## 決定(2026-10-23)

- Gemini API は**無料枠**で利用している(所有者の申告)。Google の規約(Gemini API Additional Terms の Unpaid Services、確認日 2026-10-23)では、入力と出力が製品改善に使われ、人のレビュアーが確認する場合があり、機微・機密・個人情報を送らないよう明記されている。
- そのため**検査通過ノートの自動許可は採用しない**。`ai_allowed` による手動許可を維持する。
- 認証情報は従来どおり遮断し、健康・金融・住所(`health` / `financial` / `location`)の検出は fail-closed(送らない)とする。※この機微カテゴリの fail-closed は 2026-10-25 の方針変更で廃止。認証情報の遮断は不変。
- 「AI送信許可を一括確認／一括反映」コマンドは残す。許可の付与に加えて、認証情報の検出による許可解除と、機微情報ノートの確認待ち化を担う。
- 検査を通過したことは、機微情報が存在しない保証ではない。検出は正規表現とキーワードによる。

## 送信境界(PR #85 時点。機微カテゴリ列は 2026-10-25 の方針変更で無効)

| 境界 | 認証情報 | 機微カテゴリ |
| --- | --- | --- |
| `callGemini`(最終プロンプトの検査) | 遮断 | 遮断(`AI request blocked by sensitive-data detection`) |
| Telegram の通常回答 | 遮断 | 発言ごと送信しない。履歴・関連ノートからも除外 |
| 会話の要約 | 遮断 | 該当する履歴を除外 |
| フォルダ整理の提案 | 該当ノートを除外 | 機微を含むタイトル・パス・要約は `[機微情報を含む項目]` に置き換えて送る |
| 関連ノート検索(エージェント) | 除外 | 除外 |
| AI プレビュー | 除外 | `sensitive_info_requires_confirmation` として除外 |
| 自動整理(`organizePending`) | `blocked_credentials` | 段落ごとに検査し、機微でない段落だけ送る。全段落が機微なら `pending_confirmation` |

ノート原文はどの経路でも書き換えない。

## Telegram 履歴の保存(Issue #94、所有者の判断 2026-10-23。機微カテゴリに関する特例は 2026-10-25 の方針変更で廃止)

- 機微カテゴリ(`health` / `financial` / `location`)を含む発言も、`telegram_messages` に**原文のまま**保存する。メモ自体が残らない状態を避けるため。
- 認証情報を含む発言は、従来どおり `[CREDENTIAL_BLOCKED]` に置き換えた本文だけを保存する。原文は残さない。
- 保存した原文は、AI へ送る境界で除外する。会話履歴は `selectAiSafeHistory`(`src/ai-send-guard.mjs`)で機微行と認証情報の行を取り除いてからプロンプトに入れ、最終プロンプトは `callGemini` が全文を検査する。
- 機微カテゴリを含む発言は、記憶抽出のジョブに積まない。つまり記憶候補は AI に送られず、履歴にだけ原文が残る。人の確認を経て記憶に保存する経路は、#92 の確認 UX ができてから検討する。
- 検出キーワードの調整は別 Issue(誤検知・見逃しの計測)で判断する。

## ノートの状態

| 状態 | `ai_allowed` | `review_state` | `sensitivity` | 条件 |
| --- | --- | --- | --- | --- |
| 未許可 | 0 | `ready` | — | 新規ノート。手動許可か一括反映まで AI 整理の対象外 |
| 許可済み | 1 | `ready` | `user-approved`(一括反映時) | 一括反映などで許可した後 |
| 認証情報で遮断 | 0 | `blocked_credentials` | `credentials` | 検出時。許可も解除する |
| 機微(安全な段落あり) | 変更しない | `ready` | 一括反映の保留では `sensitive` | 安全な段落だけを整理に使う |
| 機微(安全な段落なし) | 変更しない | `pending_confirmation` | `sensitive` | 整理を保留する |

内容が更新されると、同期の取り込みで `review_state` は `ready` に戻り、再検査される。

## 未決定・未実装

- `pending_confirmation` のノートを Telegram で確認して再許可する UX は未実装。現時点では、ノートを編集して再同期するか「再整理」を実行する(全段落が機微なら再び保留される)。
- 機微カテゴリの範囲。現在のキーワード検出で足りるかは未判断。
- 無料枠のまま自動許可を行う場合は、機微の分類を増やし、誤許可・漏えいの境界テストを追加してから、明示的な判断を得る。有料枠(Cloud Billing 有効なプロジェクト)へ移行した場合も、自動許可の本番適用は別の判断とする。

## 本番への適用

このポリシーは本番を変更しない。PR #85 の本番反映は #61 の方針確定まで保留している。
